# Инструкция: подготовка файлов к загрузке в БД Customs

Назначение: алгоритм подготовки Excel-файлов из `D:\projects\MyProjects\Custom\`
к внесению в базу `Customs` (SQL Server, таблица `dbo.Declarations`).

## 1. Общие правила

- Все файлы — `.xlsx` (24 шт.). `.xlsb` предварительно конвертируются в `.xlsx` вручную пользователем.
- Имена файлов могут содержать кириллические `Е` (U+0415) и `І` (U+0406) — при обращении к файлам учитывать точные символы.
- **АВТОФИЛЬТРЫ ОБЯЗАТЕЛЬНО ОТСУТСТВУЮТ.** Наличие автофильтра создаёт в `workbook.xml` имена `_FilterDatabase`, и после сохранения Excel COM (срезающего префикс `_xlnm.`) возникает конфликт имён → файл не открывается. Если автофильтр есть — убрать (через Excel: Данные → Очистить/Снять фильтр).
- Проверка конфликта: открыть архив `*.xlsx`, в `xl/workbook.xml` не должно быть двух записей `defineName` вида `_FilterDatabase` и `_xlnm._FilterDatabase` одновременно.
- Перед любыми массовыми правками — создать бэкапы всех файлов в `D:\projects\MyProjects\Custom\bak\<этап>\`.
- Заполнение колонок из другой колонки делать только при совпадении смысла значения; при расхождении формата или пустом источнике — оставлять поле пустым (НЕ выводить).
- Заголовки колонок в разных Layout могут отличаться окончаниями (`контракта`/`контракту`) — это одно поле.

## 2. Даты

- Даты из 1С могут приходить со сдвигом **+2000 лет** (datetime из 1С). Для выгрузки/вьюх использовать:
```sql
IIF(column_name >= DATEFROMPARTS(4001,1,1), DATEADD(YEAR, -2000, column_name), column_name)
```
- `Дата ВМД` в файлах встречается в трёх форматах — унифицировать при загрузке:
  - Excel-серийный номер (`45330`, `45650`),
  - datetime (`2024-03-21 00:00:00`),
  - текстовая строка (`20.01.2025` — в Layout D).

## 3. Колонки и алгоритм их подготовки

### 3.1 Митниця (ВМД)
Целевое значение: код митницы `UA######`.
- Заполнять из `Номер декларації (комбінований)` формата `1-UA209230-2024-0014813-0001` → берём `UA209230`.
- Если комбінованый пуст — источник `№ ВМД` (в нём может лежать тот же полный формат).
- Если код `UA######` не найден — оставить пустым, не выводить.
- (Выполнено для всех 12 файлов 2024: непустых значений = числу строк, non-UA = 0.)

### 3.2 Валюта
Поля: `Валюта контракта (код)`, `Валюта контракта` (A), `Валюта контракту` (C/D), `Курс валюти…`.
- **`Валюта контракта (код)`** — числовой ISO-код (`978`, `840`, `985`, `980`, `826`, `756`, `156`, `392`, `203`). Есть только в Layout A; в C/D добавляется по словарю из аббревиатуры.
- **`Валюта контракту`** — аббревиатура (`EUR`, `USD`, `PLN`, `GBP`, `UAH`, `CHF`, `CNY`, `JPY`, `CZK`). Источники: `Валюта контракта` (A), `Валюта контракту` (C/D). Это одно поле.
- **`Курс валюти контракту`** — курс. Источники: `Курс валюти` (A/D), `Курс валюти контракту` (C). Это одно поле.
- В Layout A обе колонки кода и названия идут рядом; в C/D добавлять `(код)` слева от колонки названия.
- Сопоставление аббревиатура→код:
  `EUR→978, USD→840, GBP→826, PLN→985, UAH→980, CZK→203, CHF→756, CNY→156, JPY→392`.

### 3.3 Умови поставки
Расклейка склеенных значений `FCA - Франко перевiзник` по разделителю `" - "` на два столбца:
- `Умови поставки` — только аббревиатура (`FCA`, `DAP`, `CIF`, `CPT`, `FOB`, `EXW`, `CFR`, `CIP`, `DAT`, `DPU`, `FAS`, `DDP`, `DDU`, `DAF`).
- `Умови поставки_2` — текстовая расшифровка (`Франко перевiзник`, `Поставка в місці`…).
- Если склейки нет (только аббревиатура) — `_2` оставить пустым; если колонок две — ничего не склеивать.

### 3.4 Митний режим
- Только текстовая расшифровка (например `Експорт (остаточне вивезення)`).
- Числовую колонку `Митний режим (код)` — удалять (код не нужен).
- Если в Layout колонки нет — при объединении поле остаётся пустым.

### 3.5 № ВМД (объединение «Номер декларації (комбінований)» и «№ ВМД»)
Целевое значение: номер декларации, только цифры, **без ведущих нулей**.
- Из полного формата `1-UA209230-2024-0014813-0001` извлекаем `0014813` → нормализуем до `14813`.
- Короткие номера `0008524` → нормализуем до `8524`.
- Если поле пусто или формат отличается — оставляем как есть.
- **Если в файле есть ОБА столбца** (`Номер декларації (комбінований)` и `№ ВМД`) — колонку `Номер декларації (комбінований)` **удалить** (№ ВМД уже содержит тот же номер).
- **Layout A** (2025-05…2026-07): источник номера — колонка `Номер декларації` (без скобок); переименовывается в `№ ВМД`. Лишний `Номер декларації (комбінований)`, содержащий код митницы `UA…`, — удалить.
- **Layout B** (2024 импорт): колонки нет → не трогать, при объединении пусто.

### 3.6 Кількість / одиниці виміру
- Нумерованная колонка `Кількість (одиниця виміру)` пользователю **не нужна** — удалить.
- `Одиниця виміру` (C/D) и `Додаткова одиниця виміру` (A) — это **одно поле** → единая колонка **`Од. виміру`**.
- В Layout B единиц не нет — при объединении пусто.

## 5. Особенности значений (наблюдения)

- `Умови поставки_2` в Layout A содержит **места/населенные пункты** (`LT KAUNAS`, `PL PLOCK`, `UA ODESA`…), а в C/D после расклейки — расшифровку условий поставки. При загрузке проверить, куда мапить `_2`, чтобы не смешать эти два смысла.
- `Вага брутто` есть только в A/B; в C/D только `Вага нетто` — при объединении брутто в C/D будет пусто.
- В Layout B колонка `Номер декларації (комбінований)` фактически содержит код митницы (`UA…`), а не номер.
- `Митниця (ВМД)` в Layout A: в 2025-05/06/07 могла быть пустой, а код лежал в `Номер декларації (комбінований)`. Проверять полноту перед загрузкой.

## 6. Чек-лист перед загрузкой

1. Все 24 файла — `.xlsx`, открываются без диалогов (нет конфликта имён).
2. Нет автофильтров.
3. `№ ВМД` — цифры без ведущих нулей; нет пустых там, где должен быть номер.
4. `Митниця (ВМД)` — `UA######` во всех строках, где возможно.
5. `Валюта контракта (код)` заполнена (978/840/…) по аббревиатуре.
6. `Умови поставки`/`_2` расклеены; дубликатов аббревиатур нет.
7. `Митний режим (код)` отсутствует.
8. `Кількість (одиниця виміру)` отсутствует; есть `Од. виміру`.
9. Единый перечень колонок согласован с пользователем (см. `columns_mapping.md`).
