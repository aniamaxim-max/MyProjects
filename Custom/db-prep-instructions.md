# Инструкция: подготовка и загрузка файлов в БД Customs (SQLite)

Назначение: алгоритм объединения Excel-файлов из `D:\projects\MyProjects\Custom\`
в единую таблицу `declarations` в базе `Custom/customs.db` (SQLite).

Артефакты:
- `Custom/columns_mapping.json` — каноническая схема и правила маппинга (правятся без изменения кода).
- `Custom/load_customs.py` — загрузчик с режимами `--init`, `--analyze`, `--file`.
- `Custom/export_customs.py` — выгрузка таблицы в Parquet/CSV для Power BI.
- `Custom/export_edrpou.py` — справочник ЄДРПОУ: вьюха `v_edrpou` в БД + `edrpou_export.parquet`.
- `Custom/customs.db` — результат (в `.gitignore`, коммитить не нужно).
- `Custom/customs_export.parquet`, `Custom/edrpou_export.parquet` — файлы для Power BI (в `.gitignore`).

## 1. Общие правила

- Все файлы — `.xlsx`. Служебные `~$*.xlsx` игнорируются.
- Имена файлов содержат кириллические `І` (U+0406) и `Е` (U+0415) — учитывать точные символы.
- Загрузка сопоставляет колонки **по имени** (не по номеру и не по группе), поэтому новый файл
  с уже знакомыми именами грузится без правок.
- Отсутствующие в файле канонические колонки → `NULL`.
- Строка-фантом отбрасывается, если одновременно пусты `Опис товару` и `Код УКТЗЕД`.
- Дубли не удаляются: колонка `Дубль` — флаг 0/1. Если её нет в файле, она рассчитывается
  загрузчиком (см. §4 «Дубль»); фильтрация — на стороне запросов.

## 2. Форматы и нормализация

### Даты (`Дата ВМД`) — тип TEXT `YYYY-MM-DD`
В файлах встречаются 4 формата, все приводятся к ISO:
- datetime (`2024-08-09 00:00:00`),
- Excel-серийный `int` (`45789`),
- Excel-серийный `float` (`45377.67`, с временем — берётся дата),
- текст (`10.01.2025`, только Layout D).
Если год ≥ 4001 — вычитается 2000 лет (сдвиг datetime из 1С).

### Коды УКТЗЕД — тип TEXT
В Excel хранятся числами и теряют ведущий ноль. Добиваются нулями слева:
- `Код УКТЗЕД` → до 10 знаков (`401209900` → `0401209900`);
- `Код УКТЗЕД_4` → до 4 знаков (`401` → `0401`).

### Числа
- Суммы, вес, курс — REAL с округлением до 4 знаков; запятая-разделитель → точка
  (`Курс валюти` в `2025-07-29` приходит текстом `42,2825012207031`).
- `Валюта контракта (код)` — INTEGER (978/840/…).
- `ЄДРПОУ*`, `№ ВМД` — TEXT (как есть; длины ЄДРПОУ плавают: 6/8/10 знаков, есть `0`).
- `Налив`, `Дубль` — INTEGER 0/1 (`None` → 0).

## 4. Правила маппинга

### Переименование (одно поле, разные имена)
- `Валюта контракта` (A) → `Валюта контракту`.
- `Курс валюти` (A/D) → `Курс валюти контракту` (там же `Курс валюти контракту` из C).
- `Курс валюти НБУ, $` → `Курс валюти контракту` (layout E).
- `Додаткова одиниця виміру` → `Од. виміру` (layout E).
- `Номер декларації` → `№ ВМД` (layout E).

### Валюта: дубль имени в layout E
В layout E две колонки с именем `Валюта контракта`: числовая (`978`) и буквенная (`EUR`).
Разводятся по значению: цифры → `Валюта контракта (код)`, остальное → `Валюта контракту`.

### `Дубль` — флаг дублей (если колонки нет в файле, рассчитывается автоматически)
Алгоритм (перенесён из `python/scripts/mark_duplicates.py`):
- ключ строки = (`Дата ВМД` как число дней, `ВМД`, `Вага брутто` или `Вага нетто` с 3 знаками,
  `Фактурна вартість, грн` или иная `Фактурна…` с 3 знаками);
- `ВМД` собирается как `<Номер декларації (комбінований)>/<Рік>/<Номер декларації>`
  (или `<комбінований>`, или `<Рік>/<Номер декларації>` — что доступно);
- если ключ неполный (нет даты/веса/стоимости/номера) — строка не считается;
- первая строка с ключом → `0`, все последующие с тем же ключом → `1`.
Расчёт идёт по каждому файлу отдельно (как и в исходном алгоритме).

### `Умови поставки_2` — два разных смысла (разводится по наличию `Місце поставки`)
- если в файле есть `Місце поставки` → значение идёт в `Умови поставки (розшифровка)` (C, D);
- если нет → в `Місце поставки` (A и layout E, там это город/место).

### `№ ВМД`
- C/A/D — колонка `№ ВМД` как есть (в layout E — переименование `Номер декларації`);
- B — нет своей колонки: берётся фрагмент `Номер декларації (комбінований)` после второго `/`
  (`UA100330/2024/505546` → `505546`). Ведущие нули сохраняются. Если фрагмента нет — `NULL`.

### Удаляемые (в схему не входят)
`Тип декларації`, `Митний режим`, `Митниця (ВМД)`, `№ товару`, `Посередник`, `Рік`, `Флексі`,
`Номер декларації (комбінований)` (служебный источник для B и для расчёта `Дубль`),
`Номер деклараціїОпис типа декларації`, `Номер деклараціїТип декларації`,
`Назва та адреса українського підприємства (оригінал)`, `Найменування відправника (первинник)`,
`Преференціязвільнення…` (3 шт.), а также две безымянные колонки в `2025-11-І`.

## 6. Использование загрузчика

```
python Custom/load_customs.py --init                  # полная перезагрузка всех *.xlsx
python Custom/load_customs.py --analyze               # сухой прогон по всем файлам
python Custom/load_customs.py --analyze "2025-12-Е.xlsx"   # сухой прогон одного файла
python Custom/load_customs.py --file "2025-12-Е.xlsx"      # перезагрузка одного файла
```

`--analyze` печатает: сколько колонок смаплено, список `UNMAPPED`, незаполненные канонические
колонки, число строк к загрузке и отброшенных пустых. В БД ничего не пишет.

`--file` удаляет строки с этим `source_file` и вставляет заново (идемпотентно).

## 7. Алгоритм для нового файла

1. Положить `.xlsx` в `Custom/`.
2. `python Custom/load_customs.py --analyze "файл.xlsx"`.
3. Если появились `UNMAPPED` — добавить соответствие «имя исходной колонки → каноническая»
   в `columns_mapping.json` (секция `rename`), либо в `drop`, если колонка не нужна.
   Новое каноническое поле — добавить в `canonical_columns` (там же задаётся тип).
4. Повторить `--analyze`, затем `--file "файл.xlsx"`.

## 8. Особенности данных (наблюдения)

- `2025-09-І.xlsx` содержит ~1 млн «фантомных» строк, где заполнена только `Дубль` — отсекаются
  фильтром пустых (реальных строк 10 337).
- `Єкспорт, Імпорт` и страны в B могут быть кодами (`LT`, `PL`), в A/C — названиями; нормализация
  стран не делается.
- `Митниця (ВМД)` и `Тип декларації` из схемы исключены, поэтому частично пустые значения
  (2025-05/06, 2025-07-29) не влияют на загрузку.
- `№ ВМД` без кода митницы и года не уникален — для связи используй `№ ВМД` + `Дата ВМД`
  (+ при необходимости `source_file`).
- Layout E (`2026-06-І`, лист `I`) — импорт: есть `Рік`, `Номер декларації`, `Країна відправлення`,
  `Вартість, $/кг`, `Курс валюти НБУ, $`, `Додаткова одиниця виміру`, `Флексі` (пустая) и дубль
  имени `Валюта контракта`; `Дубль` в файле отсутствует — считается загрузчиком (в 2026-06-І
  8 945 строк помечены как дубли).

## 9. Экспорт в файлы для Power BI

Power BI не имеет коннектора к SQLite, а Python-источник капризен (pandas 3.x + враппер).
Поэтому данные выгружаются в Parquet/CSV и грузятся штатным коннектором «Файл» в Desktop.

### 9.1 Таблица деклараций
```
python Custom/export_customs.py                 # customs_export.parquet (все строки)
python Custom/export_customs.py --no-duplicates # без строк, где Дубль = 1
python Custom/export_customs.py --format csv    # customs_export.csv
```
В Power BI: `Получить данные → Файл → Parquet` → `Custom/customs_export.parquet`.
Обновление: я догружаю файлы в `customs.db` → `python Custom/export_customs.py` →
в Power BI `Обновить` → `Опубликовать` (в Service обновление не жать — Python/локальный файл).

### 9.2 Справочник ЄДРПОУ
```
python Custom/export_edrpou.py                  # edrpou_export.parquet
python Custom/export_edrpou.py --format csv
```
Что берётся:
- уникальные **непустые** значения `Експорт - Код за ЄДРПОУ відправника, Імпорт - Код за ЄДРПОУ одержувача`
  (как есть, без добивки нулями; РНОКПП ФОП и короткие значения тоже остаются);
- соответствующее `Експорт - Найменування відправника, Імпорт - Найменування одержувача`;
- при нескольких написаниях имени берётся **первое по порядку загрузки** (`rowid`).
- колонки результата: `ЄДРПОУ`, `Найменування`.
В БД создаётся вьюха `v_edrpou` (и индекс `ix_declarations_edrpou`); она пересоздаётся
загрузчиком при `--init` и скриптом экспорта. Обновлять после догрузки новых файлов.
