# HANDOFF: объединение файлов Custom в SQLite (Customs)

Файл для агента. Если сессия оборвалась — попроси изучить этот файл и продолжай по нему.

## 1. Что это и что нужно от агента

Пользователя зовут **Анна**. Работаем с папкой `D:\projects\MyProjects\Custom\`: раз в месяц
Анна кладёт новый Excel-файл с таможенными декларациями, агент анализирует его и догружает
в единую SQLite-базу. Итог — таблица `declarations` в `Custom/customs.db`.

Правило общения: **обращаться к Анне по имени**, отвечать по-русски.

## 2. Артефакты (все в `Custom/`)

- `columns_mapping.json` — каноническая схема (51 колонка + `source_file`) и правила маппинга.
  Правится без изменения кода: `rename` (имя источника → каноническая), `drop`, `special_rules`.
- `load_customs.py` — загрузчик.
- `export_customs.py` — выгрузка таблицы в Parquet для Power BI.
- `export_edrpou.py` — справочник ЄДРПОУ (`v_edrpou` + `edrpou_export.parquet`).
- `db-prep-instructions.md` — подробная инструкция по алгоритму и нормализации. **Читать вместе с этим файлом.**
- `customs.db` — результат (`*.db` в `.gitignore`, не коммитится).

## 3. Рабочий процесс для нового файла

1. Анна кладёт `*.xlsx` в `Custom/` и присылает имя.
2. Анализ (ничего не пишет в БД):
   ```
   python "D:\projects\MyProjects\Custom\load_customs.py" --analyze "<файл.xlsx>"
   ```
   Смотреть: список `UNMAPPED`, число строк к загрузке.
3. Если `UNMAPPED` есть — предложить Анне решение по каждой колонке и получить подтверждение:
   - существующее по смыслу поле → добавить в `rename`;
   - не нужно → добавить в `drop`;
   - новое поле → добавить в `canonical_columns` (с типом) и в `rename`.
4. Повторить `--analyze`, затем загрузить только этот файл:
   ```
   python "D:\projects\MyProjects\Custom\load_customs.py" --file "<файл.xlsx>"
   ```
   (`--file` идемпотентен: удаляет строки с этим `source_file` и вставляет заново.)
5. Проверить результат SQL-запросами (см. §6) и коротко отчитаться.

Для Power BI (Анна публикует отчёт из Desktop) после догрузки файлов пересобрать выгрузки:
```
python "D:\projects\MyProjects\Custom\export_customs.py"
python "D:\projects\MyProjects\Custom\export_edrpou.py"
```

Осторожно: `--init` грузит **все** `*.xlsx` из `Custom/`. Если в папке лежит лишний/ошибочный
файл — сначала удалить его. `--init` нужен только при изменении схемы (добавили канонические
колонки) или для полной пересборки.

## 4. Текущее состояние (на момент последней сессии)

- В базе **887 263 строки**, 30 файлов.
- Схема: 51 каноническая колонка + `source_file`.
- Layout-группы: C (2024 экспорт), B (2024 импорт), D (2025-07-29), A (2025-05…2026-07), E (импорт/экспорт 2026, лист `I`/`E`, 49 колонок).
- Layout E: `Дубль` в файлах отсутствует и рассчитывается автоматически. Последние: `2026_05_E` (61 747), `2026_08_E` (58 686), `2026_05_I` (71 955), `2026_08_I` (68 925).

## 5. Ключевые решения (детали — в `db-prep-instructions.md`)

- Сопоставление колонок **по имени**; отсутствующие канонические → `NULL`.
- `Дата ВМД` → TEXT `YYYY-MM-DD` (4 исходных формата).
- `Код УКТЗЕД`/`_4` → TEXT с добивкой нулями слева (10/4).
- Суммы/вес/курс → REAL, округление 4 знака. `Валюта контракта (код)` → INTEGER.
- `Налив`, `Дубль` → 0/1. Если `Дубль` в файле нет — считается по алгоритму из
  `python/scripts/mark_duplicates.py` (ключ: дата + вес + фактурная стоимость + номер ВМД).
- Фантомные строки (пусты `Опис товару` и `Код УКТЗЕД`) отбрасываются.
- `Умови поставки_2`: есть `Місце поставки` → `Умови поставки (розшифровка)`, нет → `Місце поставки`.
- `№ ВМД` для 2024-импорта (layout B) — фрагмент после второго `/` из `Номер декларації (комбінований)`.
- Дубли не удаляются, только флагуются.

## 6. Проверка после загрузки (python + sqlite3)

```python
import sqlite3
db = sqlite3.connect(r"D:\projects\MyProjects\Custom\customs.db")
print(db.execute("SELECT COUNT(*) FROM declarations").fetchone())
print(db.execute("SELECT source_file, COUNT(*) FROM declarations GROUP BY 1 ORDER BY 1").fetchall())
print(db.execute("SELECT '№ ВМД', COUNT(*) FROM declarations WHERE \"№ ВМД\" IS NULL").fetchone())
print(db.execute("SELECT \"Дубль\", COUNT(*) FROM declarations GROUP BY 1").fetchall())
```

## 7. Окружение и подводные камни

- Python 3.14, `openpyxl`. `sqlite3` CLI не установлен; для просмотра — VS Code
  (расширение SQLite) или DB Browser for SQLite.
- Имена файлов содержат кириллические `І` (U+0406) и `Е` (U+0415) — различать. В PowerShell
  передавать имена лучше через `Get-ChildItem`, а не печатать вручную.
- Служебные `~$*.xlsx` (открытый Excel) игнорируются.
- `2025-09-І.xlsx` содержит ~1 млн фантомных строк (заполнена только `Дубль`) — это норма.
- Часть данных объективно пустая: `Митниця (ВМД)`, `Валютa`/`Курс` в B и 2026-*, `Дубль` в C/D.
- **Не коммитить изменения** без явной команды Анны (см. `AGENTS.md`).
